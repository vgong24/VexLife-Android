The important command-click direction is:

~~~text
screen
-> repository interface
-> production implementation
-> DAO/entity only when debugging storage
~~~

Do not make screens consume DAOs or entities directly.

`InMemoryLogHistoryRepository` and `LogHistoryFixture` exist so previews/tests can reproduce exact
states through the same repository contract instead of teaching production code about mocks.

There is deliberately no generic BaseRepository<T>.

The CGM Partner patient zero keeps its domain durable contract at `cgm/CgmStore.kt` and places only
the Room realization under `data/cgm`. One already-admitted Partner Observation maps to explicit SQL
columns carrying source identity plus Connection occurrence provenance. Room restoration reconstructs
historical Observation/Signal values directly into Store truth; it does not invoke Partner Decoder or
Receiver again.

```text
Partner Observation
-> CgmStore.commit(...)
-> RoomCgmStore
-> CgmObservationDao / Entity

process restart

Room rows
-> historical Observation values
-> CgmStore Snapshot
-> CgmFamily

ENTITY_RESTORED != PARTNER_SIGNAL_RECEIVED
```

The tracked Room schema is generated by KSP/Room. Do not hand-author a schema identity hash.

Log History demonstrates a multi-statement @Transaction boundary (insert + retention prune).
User Profile demonstrates single-row upsert/update and schema migration without pretending profile
data owns future VexHome/VexStream connection state.

See `docs/foundation/DATA-REPOSITORY.md`.
