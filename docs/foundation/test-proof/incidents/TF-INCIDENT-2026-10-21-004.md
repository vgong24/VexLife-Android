## Known observability gap

Before the current hardening candidate, the exact semantic wait:

~~~text
waitForTag(elementId)
    -> merged Compose semantics only
~~~

and a failure rendered large merged/unmerged trees into the thrown assertion.

The SDK coordinator retains only a bounded tail of the instrumentation log. A large semantic tree can
therefore push the exact target comparison or Activity summary outside the retained tail.

That is an evidence-system weakness regardless of the underlying intermittent cause.

## Hardening candidate — PR #148

Current candidate head:

~~~text
358bf6de2fcedb9948842b6da66372032cb296fb
~~~

The test-only hardening now:

~~~text
exact Vex semantic tag
    -> search merged semantics
    -> if absent, search unmerged semantics
    -> click the same exact semantic address once

on failure
    -> retain merged exact-target count
    -> retain unmerged exact-target count
    -> retain Activity lifecycle/finishing/destroyed/window-focus state
    -> capture failure screenshot
    -> append compact VEX_SEMANTIC_WAIT_FAILURE footer after verbose trees
~~~

This does **not**:
- search by title/text/position;
- add a sleep;
- automatically retry the action;
- reset the app and try again;
- change production VexStream menu behavior;
- explain the historical failure.

Therefore:

~~~text
hardeningState = CANDIDATE
failureStatus = OPEN_UNEXPLAINED
~~~
